\begin{abstract}
Singapore telecommunications operators receive continuous, unsolicited customer feedback through online forums, but the volume, informality and platform-specific language make manual monitoring difficult. This project develops an end-to-end pipeline that collects forum discussions, normalises heterogeneous records, identifies telecommunications brands, assigns sentiment and issue labels, and presents findings through static and interactive dashboards. The implemented dataset contains 15,504 cleaned records collected mainly from Reddit and HardwareZone (HWZ). After removing ambiguous uses of the Eight brand name, a focused dashboard sample contains 158 telco-relevant records: 96 (61\%) are labelled happy, 34 (22\%) not happy and 28 (18\%) neutral. Network quality is the largest primary issue theme (41 records, 26\%), followed by app and account (39 records, 25\%) and general discussion (18 records, 11\%).

The system combines deterministic brand matching, VADER sentiment, a keyword issue taxonomy, an optional Hugging Face sentiment model and OpenAI chat-completions classification. Independent human labels on a blinded 300-row representative sample (295 telco-relevant rows) show that \textbf{gpt-4o-mini-2024-07-18} improves sentiment over VADER (macro F1 0.631 versus 0.360; accuracy 67\% versus 37\%). \textbf{gpt-4o-2024-08-06} is similar on sentiment (macro F1 0.623) and still loses to keyword issue rules when it labels every row (macro F1 0.600 versus 0.639). A hybrid that keeps rule labels and applies GPT-4o only to unresolved \texttt{general\_discussion} rows raises issue macro F1 to \textbf{0.680}. That hybrid was then applied to 8,786 unresolved corpus rows (29.7 minutes, estimated \textbf{\$3.45}). The 158-row dashboard sample uses VADER sentiment and hybrid issue labels (keyword rules, then GPT-4o on unmatched \texttt{general\_discussion} rows). An earlier 150-record VADER ``100\% accuracy'' file is discarded because its labels match VADER exactly and were model-prefilled. The operational recommendation is therefore hybrid: LLM sentiment (mini is sufficient) and keyword rules plus GPT-4o on unresolved issues. The business analysis indicates that operators should prioritise transparent pricing and network-tier communication, location-specific network evidence, robust number-porting journeys and clearer roaming propositions. The principal contribution is a reproducible analytics workflow that converts noisy forum data into decision-oriented signals while making its evidential limits explicit.
\end{abstract}

\section{Introduction}

\subsection{Business context}

Mobile customers discuss price plans, coverage, roaming, porting and service failures in public online communities. These discussions can reveal emerging pain points earlier and in more detail than periodic surveys. They are also difficult to analyse reliably: posts contain Singlish, abbreviations, sarcasm, quoted text, multiple brands and off-topic uses of ambiguous brand names such as ``Eight'' or ``M1''.

This project asks how a telecommunications operator can convert such unstructured discussion into a repeatable source of customer insight. The objective is not to infer population-level satisfaction or replace operational metrics. Instead, the pipeline is designed as an early-warning and exploratory decision-support system that helps analysts locate themes, compare discussion contexts and inspect representative records.

\subsection{Objectives}

The project has five objectives:

\begin{enumerate}
  \item collect relevant discussions from multiple online platforms;
  \item clean and standardise heterogeneous post and comment records;
  \item detect mentioned operators and classify sentiment and service issues;
  \item compare lightweight baselines with more context-aware model options; and
  \item translate the results into actionable recommendations through a dashboard.
\end{enumerate}

\subsection{Research questions}

\begin{description}[leftmargin=0cm,style=nextline]
  \item[RQ1.] What sentiment and issue themes appear most frequently in the collected Singapore telco discussions?
  \item[RQ2.] How do discussion patterns differ between Reddit and HWZ, and across telco brands?
  \item[RQ3.] What additional value can a context-aware model provide over VADER sentiment and keyword-based issue rules?
  \item[RQ4.] How can the extracted signals support concrete decisions by telco operators?
\end{description}

\subsection{Scope and claimed contribution}

The repository implements collection modules for HWZ, Reddit and Twitter/X, although the analysed records are mainly from Reddit and HWZ. It includes preprocessing, brand detection, sentiment labelling, issue extraction, evaluation scripts and two dashboard formats. The report only claims findings supported by persisted repository outputs. GPT-4o-mini is evaluated on human labels for the representative and challenge sets; GPT-4o is evaluated on the representative set and used on unresolved corpus issues. The 158-row dashboard sample remains VADER for sentiment and uses the hybrid issue overlay where posts match the corpus file.

\subsection{Preprocessing}

The preprocessing module maps platform-specific fields to a common schema, removes empty, placeholder and very short records, and can optionally retain English-language records using language detection. The common schema includes \texttt{source}, \texttt{thread\_title}, \texttt{post\_text}, timestamp fields and identifiers. Normalisation allows downstream modules to process different platforms without source-specific model code.

The current workflow retains post text that may include informal spelling, emoji and HTML entities because these features can carry sentiment. This is useful for analysis but also creates modelling challenges. The dashboard therefore presents aggregate indicators and traceable examples rather than treating model output as verified customer facts.

\subsection{End-to-end architecture}

The implemented sequence is:

The static dashboard generator is deliberately lightweight and produces a standalone HTML report. The Streamlit application supports source, brand, sentiment and date filters, issue breakdowns, time trends and cross-brand views. Together, they support both executive communication and analyst exploration.

\section{Analytical Methods}

\subsection{Telco detection}

Brand mentions are identified by regular expressions over the concatenated thread title and post text. The tracked labels include Singtel, StarHub, M1, SIMBA, Giga, Eight, Zym and redONE, with additional MVNO keywords used by the dashboard. Multiple brands can be assigned to one record. This design is transparent and inexpensive, but ambiguous names and thread-level context can create false positives. For example, a post containing the ordinary word ``eight'' may be incorrectly associated with the Eight brand unless the surrounding context is considered.

\subsection{Sentiment baseline: VADER}

VADER is a lexicon- and rule-based sentiment method designed for social-media text \cite{hutto2014vader}. For each post, the pipeline obtains a compound score and maps it to:

\begin{equation}
\text{label}(s)=
\begin{cases}
\text{happy}, & s \geq 0.05,\\
\text{not\_happy}, & s \leq -0.05,\\
\text{neutral}, & \text{otherwise}.
\end{cases}
\end{equation}

VADER is a suitable operational baseline because it runs locally, is deterministic and requires no paid API. Its limitation is contextual understanding. It can misread sarcasm, negation over long passages, mixed opinions, quoted complaints and the difference between sentiment towards a telco and sentiment towards another topic in the same thread.

\subsection{Context-aware sentiment option}

The benchmark module supports \texttt{cardiffnlp/twitter-roberta-base-sentiment-latest}, a RoBERTa-family model adapted to social-media sentiment \cite{loureiro2022tweeteval}. Its positive, negative and neutral outputs are mapped to the project's three business labels. The persisted benchmark states that the required \texttt{transformers} package was unavailable, so no transformer metrics are reported.

The main labelling module also implements LLM sentiment through an OpenAI-compatible chat-completions interface. Its configured default is \textbf{GPT-4o-mini}. Formal comparison uses the snapshots returned by the API, \textbf{gpt-4o-mini-2024-07-18} and \textbf{gpt-4o-2024-08-06}, with temperature 0 and JSON object responses in batches of ten posts. An earlier 100-record HWZ file contains 100 neutral LLM labels and no model-version metadata; that file is treated as a failed or fallback run and is not used as evidence. The 15,504-row corpus still has no LLM sentiment column; corpus dashboards use VADER.

The static dashboard overlays those hybrid labels onto the 158-row sample (97 posts matched; unmatched HWZ rows still use keyword inference).

\section{Evaluation Design and Evidence}

\subsection{Required metrics}

For a three-class sentiment task, overall accuracy alone can hide poor performance on minority classes. The evaluation module therefore calculates a confusion matrix and per-class precision, recall and F1, together with macro F1. For issue extraction, the appropriate measures are per-class precision, recall and F1 under a multi-label protocol, plus micro and macro averages.

Model comparison uses the same independently annotated records. Runtime is measured on the same machine, and the API run records input tokens, output tokens, retries, the exact returned model identifier and estimated cost from the provider list prices supplied at run time.

\subsection{Independent annotation}

A blinded evaluation package was generated without VADER, transformer or LLM columns. Threads were split so that representative and challenge posts do not share threads, with at most five comments per thread. Annotator~A labelled:

\begin{itemize}
  \item a 300-row representative sheet (214 Reddit, 86 HWZ), of which 295 posts were telco-relevant;
  \item a 100-row challenge sheet reserved for harder cases (negation, sarcasm or Singlish cues, mixed brands, weak VADER scores, long posts).
\end{itemize}

A 100-row second-annotator overlap sheet exists, but no independent Annotator~B labels were used in this report, so inter-annotator agreement is not claimed. Headline metrics use only the representative relevant rows. Challenge metrics are reported separately and are not pooled.

An earlier 150-row file reported 100\% VADER accuracy. Those labels match VADER exactly and can be created by prefilling from the model, so that file is treated as leakage and is not used as evidence.

\subsection{Challenge set (reported separately, $n=100$)}

The challenge set was sampled from held-out threads using a difficulty score. It must not be mixed into Table~\ref{tab:headlinemetrics}. On these 100 posts, GPT-4o-mini sentiment accuracy is 0.80 and macro F1 is 0.773, versus VADER 0.50 and 0.491. Issue macro F1 is nearly tied (rules 0.499, LLM 0.470). The sentiment advantage therefore holds on harder text; all-row issue tagging still does not flip to mini. Devices recall remains 0.083 (1 of 12). App and account has only three positive labels, so that class F1 is not interpretable. GPT-4o was not rerun on the challenge set.

\subsection{Qualitative disagreements}

Examples are paraphrased from \texttt{qualitative\_disagreements.csv}. They illustrate why surface lexicons fail and why all-row LLMs drop device labels.

\begin{itemize}
  \item \textbf{REP-0003} (``SingTel eSIM still down''): human and LLM \texttt{not\_happy}; VADER \texttt{neutral}. Short status updates lack sentiment words.
  \item \textbf{REP-0014} (switched after 5G drops, cheaper 500\,GB plan): human and LLM \texttt{not\_happy}; VADER \texttt{happy} because of ``better'' and ``just \$12''.
  \item \textbf{CHL-0005} (``Smoooooooth as baby butttttt''): human and LLM \texttt{happy}; VADER \texttt{neutral}. Elongated slang is outside the lexicon.
  \item \textbf{CHL-0029} (nationwide outage, ready to port out): human and LLM \texttt{not\_happy}; VADER \texttt{happy}. Switching intent is a complaint, not praise.
  \item \textbf{REP-0015} (``Starhub, no ONR, no CGNAT''): human and rules label \texttt{devices}; GPT-4o-mini returns \texttt{general\_discussion} and flips sentiment to happy. Equipment jargon is a systematic all-row LLM miss; the unresolved hybrid keeps the rule \texttt{devices} tag on this class of post.
\end{itemize}

\section{Findings}

The subsections below describe the 158-row dashboard sample, which remains VADER-labelled for sentiment and uses the hybrid issue overlay. It should not be confused with the 295-row evaluation.

General Discussion shrank after the GPT-4o overlay (97 of 158 posts matched the hybrid corpus file; unmatched HWZ rows still use keyword inference), but a residual bucket remains.

\subsection{Platform differences}

Reddit contributes 67 relevant records, of which 49\% are happy, 30\% not happy and 21\% neutral after rounding. HWZ contributes 91 records, with 69\% happy, 15\% not happy and 15\% neutral. The 15-percentage-point difference in negative tone is substantial within the sample, but platform and topic are confounded: Reddit records are more complaint-oriented, while the HWZ selection over-represents plan-launch discussion. The difference therefore describes these samples, not inherent sentiment of each platform.

\subsection{Dashboard design}

The static dashboard and Streamlit app now pair each chart with a takeaway rather than a descriptive title. Both lead with a weekly 30-minute huddle playbook: (a) not-happy posts in Network Quality, App \& Account or Porting, only if $n$ meets a threshold; (b) open ten source posts; (c) match remaining items to tickets or outages; (d) assign one owner; (e) check next week whether the share fell. Brand negative-tone ranks require at least ten mentions. Never publish a league table from $n=6$.

\begin{itemize}
  \item \textbf{Sentiment:} forum tone is a screen, not CSAT; VADER likely overstates happiness.
  \item \textbf{Source:} start complaint review on Reddit; HWZ is launch-thread heavy.
  \item \textbf{Issue volume:} route Network Quality and App \& Account first; General Discussion is a residual after the GPT-4o overlay.
  \item \textbf{Not-happy by issue:} volume is not severity---porting can be rare but retention-critical.
  \item \textbf{Brand mentions:} talk volume is not market share or dissatisfaction.
  \item \textbf{Negative tone:} rank only brands with at least ten mentions; suppress Giga/SIMBA/Zym league-table use.
  \item \textbf{Quotes and table:} inspect the posts behind a spike before assigning an owner.
\end{itemize}

Streamlit adds the same captions, a week-level trend with a minimum-volume alert rule, and a not-happy rate chart with mention counts on hover. Outputs remain screening signals, not verified customer facts.

\section{Business Recommendations}

Each recommendation names an owner, an action and a check. Forum counts are a triage queue, not proof of market failure.

\subsection{CX / digital: own App \& Account friction}

App and account access is the second-largest primary theme in the dashboard sample, just behind network quality. Login failures, OTP gaps, white screens and chatbot dead-ends should sit with digital CX. After each app or chatbot release, sample forum posts tagged App \& Account and track time-to-human and login-related complaint share. Success is fewer ``cannot log in / no OTP'' posts in the following window, not a higher happy rate on VADER.

\subsection{Network: replace national coverage claims with local proof}

Network quality is the largest actionable theme and is location-specific (MRT, buildings, 5G SA). Network and CX teams should join named-location forum posts to tickets and cell-level telemetry, then publish indoor/MRT guidance and known fixes. Success is a drop in tickets for the named location after remediation, not a press claim of ``best coverage''.

\subsection{Product / MVNO partners: disclose host network and tier}

GOMO/Singtel, Eight/StarHub and Zym discussions show customers buying price and discovering the host later. Product and partnership teams should state host network, 5G SA support, fair-use rules and who owns escalation at checkout. Success is fewer ``which backend?'' threads and fewer mistaken Eight mentions of the ordinary number eight.

\subsection{MNP operations: treat porting as a retention event}

Porting is a small share of posts but high severity (document mismatch, rejected ports, 30-day activation fees, IMDA). Operations should return a specific reject reason and next step, and jointly own avoidable-reject rate and median port time. Success is fewer repeat ``StarHub rejected my port'' narratives, not more mention volume.

\subsection{Commercial: make price and promotion fulfilment auditable}

Bridge-mode fees, intro versus recurring prices and missed promos drive switching talk. Commercial teams should publish comparable plan facts and treat promotion fulfilment as an operational metric. Success is a fall in fulfilment complaints, not a lower list price alone.

\subsection{Roaming: intervene before the bill}

Malaysia, New Zealand and Bali threads mix genuine praise with failed attach, 3G sunset and divert charges. Roaming product should ship an in-app ``travelling to X'' checklist (activation, coverage, overage cap). Success is fewer destination-specific bill-shock posts.

\subsection{Insight huddle: operate the dashboard as an alert-and-review tool}

Do not publish a brand league table from $n=6$. A weekly 30-minute process is enough:

\begin{enumerate}
  \item flag not-happy posts in Network, App \& Account or Porting only when that week's volume clears a minimum (for example 20 posts);
  \item open about ten source records and discard sarcasm, mixed-brand and off-target labels;
  \item triangulate with tickets, outages and billing;
  \item assign one owner and a response date;
  \item next week, check whether that issue's share fell.
\end{enumerate}

Use VADER on the full firehose for a first pass, then GPT-4o-mini for sentiment on a reviewed sample. For issues, keep keyword rules and apply GPT-4o only to \texttt{general\_discussion} rows. Keep a person in the loop before any public reply. That mix is the business reading of the evaluation, not a model contest.

\section{Limitations and Ethical Considerations}

\subsection{Representativeness and platform bias}

Forum contributors are self-selecting and are not Singapore mobile users at large. The cleaned corpus has 15,504 rows but only about 2,700 unique comment texts and about 150 unique thread titles; most rows are duplicates or replies in the same event. About 7,589 rows have no detected telco brand and must not drive brand charts. The full corpus is about 97\% Reddit (15,050 versus 454 HWZ), while the dashboard sample was constructed as 67 Reddit and 91 HWZ relevant rows. Those two mixes are not interchangeable. Reddit over-represents outages, scams and ``which MVNO?'' threads; HWZ over-represents SIM-only launches. There are no Twitter/X records, app-store reviews, tickets or NPS in the analysed set. Results cannot be generalised to market share, population sentiment, churn or Net Promoter Score. Brands with fewer than ten mentions (Giga, SIMBA, redONE) are too small for investment ranking.

\subsection{Unequal and dependent observations}

One record can mention several brands, so mention counts are not unique customers. Comments in a thread are not independent: they respond to a shared outage or launch. A long Singtel downtime thread can dominate network counts without implying a nationwide prevalence. Mixed-brand posts were often labelled \texttt{neutral}, which can hide a Singtel complaint sitting next to StarHub praise. Charts therefore suppress negative-tone ranks below ten mentions and should be read with unique-thread counts in mind.

\subsection{Label quality and LLM misclassification}

Dashboard and corpus sentiment are VADER. On 295 independent labels VADER not-happy recall is 0.34, so the dashboard's 61\% happy share is likely too optimistic. Keyword issue rules over-trigger on generic terms such as ``plan'' and leave 57\% of the full corpus in \texttt{general\_discussion} before the hybrid pass (40\% after GPT-4o on unresolved rows). The 158-row dashboard overlays those hybrid labels on 97 matched posts; unmatched HWZ rows still use keyword inference. Human gold labels are single-annotator; Cohen's $\kappa$ is not reported.

GPT-4o-mini-2024-07-18 is better at tone (macro F1 0.631 versus 0.360) and worse at all-row multi-label issues (0.504 versus 0.639). GPT-4o-2024-08-06 does not beat mini on sentiment (0.623) and still loses to rules when it labels every issue row (0.600). All-row models systematically under-label Devices relative to rules (GPT-4o recall 0.25 versus 0.81), often return one topic when the post has several, and GPT-4o-mini over-uses \texttt{neutral} on the challenge set. Those errors are prompt- and snapshot-specific. The unresolved hybrid raises issue macro F1 to 0.680 on gold labels, but the 8,786 corpus reassignments have no second human check; the 2,080 extra network-quality tags in particular should be sampled before they drive a huddle. Forum text sent to a vendor API is also a privacy limit: production jobs must not submit NRIC, phone numbers or other identifiers. The defensible stance is therefore triage plus human review, not automated league tables.

\subsection{Privacy and responsible use}

Although forum posts are publicly accessible, public availability does not remove ethical obligations. Reports should avoid usernames and unnecessary verbatim quotations, minimise stored identifiers, restrict raw-data access and comply with platform terms. The system should analyse themes, not profile individuals. Credentials and API keys must be stored in environment variables or a secret manager and must never appear in code, reports or version control.

\section{Future Work}

Remaining work is operationalisation. LLM issue extraction is complete: keyword rules plus GPT-4o on unresolved rows, evaluated on 295 gold labels and applied to the 8,786-row residual.

\begin{enumerate}
  \item Obtain a second annotator on the 100-row overlap sheet, compute Cohen's $\kappa$ and adjudicate disagreements.
  \item Install \texttt{transformers} and run Twitter-RoBERTa on the same 295 records.
  \item Spot-check the 2,606 corpus rows that GPT-4o moved out of \texttt{general\_discussion}, especially the extra network-quality tags, before treating huddle counts as incidents.
  \item Add thread-aware and target-aware modelling so that sentiment is attached to a specific operator rather than copied to every brand mentioned in a record.
  \item Validate dashboard alerts against internal service tickets and network events before operational deployment.
\end{enumerate}

\section{Conclusion}

This project demonstrates a complete technical path from online forum collection to operator action. In the 158-record dashboard sample, Network Quality and App \& Account are the first teams to route, while porting is treated as high-severity despite low volume. Charts are captioned as takeaways, not as CSAT or brand league tables. The evaluation supports a hybrid operating model: VADER and keyword rules on the firehose, GPT-4o-mini for sentiment, GPT-4o only on unresolved issues, and a weekly human huddle before any public response.

The analysis also demonstrates why model governance matters. A perfect score from non-independent labels is less useful than an imperfect but credible benchmark. On 295 blinded human labels, gpt-4o-mini-2024-07-18 raises sentiment macro F1 from 0.360 (VADER) to 0.631 at under \$0.01. gpt-4o-2024-08-06 does not improve sentiment (0.623) and loses to keyword rules on all-row issues (0.600 versus 0.639), but the unresolved-only hybrid reaches issue macro F1 0.680. Applying that hybrid to 8,786 corpus rows cost about \$3.45. The defensible deployment choice is therefore LLM sentiment, rule-based issues plus GPT-4o on the residual, with human review of alerts. With that mix, the system can serve as a practical early-warning layer alongside, rather than in place of, customer-service and network data.
